# 图约束共边与剩余客厅

## 生成流程

RL 移动独立房间种子，估算房间区域、边界间距、共边、面积与公共区域连通性。精确生成按顺序进行：

1. 预留户门内侧公共区域，独立房间不能占用。
2. 独立房间连续坐标生长，受完整固定结构约束。
3. 根据 adjacent 图边联合拟合两侧房间的整条边。面积达标后仍可调整共边：既可移动对边保持面积，也可在允许偏差内伸缩；禁止引入硬错误或破坏已满足的关系。
4. 用建筑可用区域减去全部独立房间，差集整体归入客厅。不能只保留最大碎片并丢掉其他区域。
5. 检查私有房间面积、长宽比、形态、结构避让、重叠；检查公共空间连通、净宽、户门及入口预留区域；检查每条实际共边和剩余未分配面积。任何失败仍是 unresolved。

这是受种子约束的有限候选搜索，不是任意种子下都能解出可行图的保证。图不改变房间 ID，不用图线冒充真实墙边；门内侧公共空间的验证也不等于全部室内门或交通路径已被证明。

## 配置与训练

`TargetSpaces` 中 `living.role: residual` 表示客厅是公共区域图节点。它不创建种子动作、actor 或独立矩形，原矩形数据仅作为历史参照保留。独立房间默认 `role: agent`。

当前 retrofit 为 6 个图节点、5 个策略，观测矩阵 5×62。客厅参与邻接、区域面积和连通性反馈；不会因不满足矩形度或旧矩形复用率而受罚。公共空间奖励分配给独立房间策略，因为它们共同决定剩余区域。邻接奖励以实际代理共边为主，区域间距提供尚未贴合时的连续反馈；精确验收仍不可被代理奖励代替。

- `living.residual_min_area`：公共空间最低面积，当前 30 ㎡。旧客厅目标面积和最大矩形面积不再控制剩余区域。
- `living.min_width`：公共空间净宽检查，当前 0.9 m。采用内缩半净宽后是否仍为单个非空区域的保守几何检查，不代表完整通行设计或规范合规。
- `ExistingBuilding.door_positions`：户门两个端点，整段必须在建筑边界上。当前显式保存原编辑器默认端点 `(13.8,0)`、`(16.2,0)`。
- `SeedGrowth.entrance_depth`：门内侧预留深度，当前 0.9 m。固定结构阻挡时拒绝配置，不移动或穿透结构。
- `SeedGrowth.fitting_area_tolerance`：共边调整的目标面积偏差，默认 12%，同时受原面积范围约束；不能通过无限放大房间换取邻接。

上述数值是可编辑的设计参数，不是声称适用于所有住宅的规范值。带 residual 的配置通过 GUI 或原矩形训练脚本启动时均转到图种子流程。新模型记录 `graph_partition_v2` 目标版本及全部图节点 ID，旧检查点不能直接续训；旧产物可以继续读取。
